# 首次安装自检记录（v0.7.2）

日期：2026-10-29。检查对象为本项目的首次安装、无服务凭据运行边界、可选依赖、命令帮助和服务配置说明，不是新作品的审美评测。

## 发现并修复

| 问题 | 修订 |
|---|---|
| 基础剪辑与全部云服务混在一起，首次使用没有明确起点 | 首页链接首次使用指南；先用自有材料，不强制填写服务Key |
| 只复制Skill会遗漏根入口、模板和插件 | 明确保留完整目录；首次可让AI直接读取本目录技能，不先修改全局配置 |
| Google音乐Key与Google Cloud登录容易混淆 | 按当前代码逐项列出环境变量、钥匙串、ADC及项目；说明不通用 |
| 子命令--help被总入口截获 | 转发到实际配音/音乐等子命令，回归验证真实选项可见 |
| Node存在但版本过旧时，打标安装/配置仍会继续 | 需要Node20+，在执行前拦截；参考切镜仍是Node18+，不混用要求 |
| 豆包实现使用proxy=None，但最低依赖仍允许websockets14 | 最低改为15，保留<17范围；自检检查实际版本范围，[上游变更记录](https://websockets.readthedocs.io/en/stable/project/changelog.html)说明该参数的引入 |
| 独立本地分析即使不提交也强制查库 | 无配置且不在受保护工作区时可只准备证据，不建库；已有配置、显式选库、受保护工作区不能降级；--submit仍要求库 |
| 本机Python默认信任链使pip安装失败 | 记录实际证书错误；用系统可信CA完成隔离安装，未关闭验证；指南加入[Python官方证书安装方法](https://docs.python.org/3/using/mac.html)和可信CA排错 |

## 实际执行范围

使用独立解压目录、新建Python虚拟环境，移除测试子进程中的服务凭据环境变量，模拟无统一素材库配置。没有改动真实HOME、已有账号、钥匙串、ADC或生产库。

复用了本机FFmpeg、Node/npm运行时和公开依赖缓存。安装依赖时显式使用系统可信CA。因此这是隔离的Python/目录测试，不是全新电脑或完全无缓存的操作系统安装。

| 场景 | 结果与边界 |
|---|---|
| 无扩展Python包，基础doctor | 基础制作依赖通过；numpy/websockets缺失单列，不误报全部不可用 |
| 无扩展Python包，制作编解码 | 7项真实编解码/输入边界测试通过；合成测试夹具不是宣传片样例 |
| 无服务Key，空库初始化 | 临时空库初始化成功，没有读写生产主库 |
| 无服务Key，配音/音乐dry-run | 准备请求成功，新增云请求0；不证明密钥或权限有效 |
| 安装扩展requirements | 新venv安装numpy2.5.4、websockets16.1.1、certifi2026.10.23；默认TLS失败后显式采用系统可信CA |
| 修订候选全套回归 | 49项通过，包含不暴露密钥、不尝试认证、旧依赖拒绝和无库本地分析保护等边界 |
| 独立本地分析，无Key、无库 | 实际生成切点/精度/声音证据和报告；未建数据库，未上传；退出1明确表示语义未完成，不冒充完整精拉 |
| 打标首次安装依赖 | 独立解包目录执行npm ci --ignore-scripts成功，doctor识别依赖，MCP配置可生成 |
| 全模块运行依赖doctor | 扩展安装后依赖检查通过，不代表云服务、宿主注册或视频效果通过 |

本轮新增5项首次安装边界测试与2项无库分析保护测试，原42项保留，总计49项。
