# 第一次使用：先用自己的素材做一条片

第一次不必开通所有云服务，也不必先填API Key。基础剪辑、导出、自建素材库、动效检索、本地证据和打标工具本身不要求云服务密钥；AI宿主自己的账号或模型配置另算。

## 1. 下载并保留完整目录

从[发行页](https://github.com/oumomomo/promo-video-workflow-kit/releases)下载最新测试版ZIP，解压到一个固定的项目文件夹。所有命令都从能看见`README.md`、`video_make.py`、`video_setup.py`和`skills/`的这一层执行，不要在ZIP里运行。

已安装Git和Python时，也可在打算存放项目的目录打开终端，下载完整仓库：

```sh
git clone https://github.com/oumomomo/promo-video-workflow-kit.git
cd promo-video-workflow-kit
python3 video_setup.py doctor
```

Windows把最后一行换成`py -3 video_setup.py doctor`。`git clone`是下载，`doctor`是检查；没有自动安装Python、FFmpeg、模型额度或宿主插件。自检发现缺项时再按下面的模块说明处理。若需要复现已发布的固定版本，可将第一行改为`git clone --branch v0.7.2 --depth 1 https://github.com/oumomomo/promo-video-workflow-kit.git`。

在能够读取本地文件、运行命令的AI工具中打开这个文件夹。第一次可以直接让AI读取本目录的技能文件，不需要先把全部技能复制到全局目录。

如果宿主支持Skill安装，按宿主说明安装整个技能目录；扩展工具依赖的同包技能保持同级。原仓库目录仍要保留：根目录命令、安装说明、插件与检查模板不在单个SKILL.md内。只复制一个SKILL.md、或删掉解压目录，都不算完整安装。

## 2. 先检查基础环境

安装[Python 3.10+](https://www.python.org/downloads/)及[FFmpeg/ffprobe](https://ffmpeg.org/download.html)，FFmpeg需含libx264且能从终端找到。基础制作不要求Node或额外Python包。

macOS/Linux：

```sh
python3 video_setup.py doctor
```

Windows安装了Python Launcher时：

```powershell
py -3 video_setup.py doctor
```

默认退出状态只看基础制作。其他模块缺依赖会单独列出，不妨碍已有素材剪辑。`library`只需Python；参考切镜需Node18+；打标插件需Node20+、npm及其依赖。

自检只看运行依赖和环境变量是否存在，不读密钥值、不读钥匙串、不登录Google、不请求生成、不修改配置。密钥存在不等于有效；依赖齐全不等于服务权限、宿主工具或审美已验收。

## 3. 准备第一条片的真实材料

准备2–4段你有权使用的产品录屏/视频，或2–4张产品图片，以及要表达的一个核心卖点。需要声音时可提供已有旁白与有使用依据的音乐文件。真实产品说明、功能和数据也请一并提供。

先用已有材料验证制作和审片；需要人物动作、复杂交互或3D时再接合适工具。几张图片加推拉不会自动变成真实操作或人物动作。

把下面整段交给AI即可：

> 我是首次使用者。请先读取本目录README、docs/首次使用.md，以及skills/video-making-kit/SKILL.md和它要求的宣传片避雷清单。先运行video_setup.py doctor，指出基础制作缺什么；只安装本次需要的依赖。然后使用我提供的材料制作一条15秒宣传片，保持真实产品结构和行为。先列素材缺口并写稿、做分镜；本次不调用云端生成、分析或配音服务，不要求我先填密钥。声音只使用我提供且有依据的文件；没有声音就明确记录静音方案。交付实际视频、工程、检查范围和实际可用的审片入口。不要把技术测试或静图推拉称为效果已通过。

如果你希望使用付费生成服务，可以把“不调用云端”的限制改为本次明确授权的服务和范围；不要为了填满流程购买所有账号。

## 4. 跑通后，再按需要启用模块

| 想增加什么 | 要做什么 | 服务密钥 |
|---|---|---|
| 自己的素材库 | 按[建库方法](建立自己的素材库.md)初始化空库；已有统一库继续用原库 | 不需要 |
| 本地切镜/关键帧 | Node18+、FFmpeg；使用自己的本地原件 | 不需要 |
| 本地声音/动作测量 | 在当前Python环境安装numpy；云语义部分可暂不启用 | 不需要 |
| 中文生成旁白 | 安装扩展Python依赖，配置自己的豆包语音API Key | 豆包语音Key |
| Google生成音乐 | 建议安装certifi，配置自己的Google AI Studio Key | Gemini API Key；也可显式走ADC |
| 英文生成旁白 | Google Cloud CLI、自己的项目、Cloud Text-to-Speech权限和ADC登录 | Google云账号登录；本包不以Gemini Key代替 |
| 云端视频/声音分析 | numpy、自己的Google Cloud项目、Vertex服务及ADC登录，并有本次上传授权 | Google云账号登录；不用Gemini Key |
| 视频打标 | Node20+，`python3 video_review.py setup`，再按宿主接入MCP | 插件本身不需要Key |

配音/分析的依赖建议放虚拟环境，避免装进系统Python。macOS/Linux：

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r skills/video-production-tools/requirements.txt
python video_setup.py doctor --feature analysis
```

Windows PowerShell可不修改脚本执行策略，直接使用虚拟环境的Python：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r skills/video-production-tools/requirements.txt
.\.venv\Scripts\python.exe video_setup.py doctor --feature analysis
```

后续命令也使用同一个虚拟环境的Python。安装成功却仍提示缺包时，先核对自检打印的Python路径，不要反复换环境安装。

服务获取及填写方式见[密钥与服务配置](密钥与服务配置.md)；打标接入见[插件安装](打标插件安装.md)。Remotion等复杂动效的依赖按实际采用配方安装，不在第一步强制安装整个生态。

## 5. 常见卡点

- `ffmpeg/ffprobe`缺失：检查安装和PATH，再打开新的终端；填API Key不能解决。
- 找不到`video_make.py`：当前目录不在解压根目录，或只复制了技能文件。
- `ModuleNotFoundError`：在运行命令的同一个Python里安装requirements，核对虚拟环境。
- 安装依赖时报`CERTIFICATE_VERIFY_FAILED`：先修复Python信任链，而不是将后面的“No matching distribution”理解成没有这个包。python.org的macOS安装可按[官方说明](https://docs.python.org/3/using/mac.html)运行对应Python安装目录的`Install Certificates.command`。也可在管理员提供的可信CA存在时给pip传`--cert`；本轮macOS测试使用系统`/etc/ssl/cert.pem`成功，例如`python -m pip --cert /etc/ssl/cert.pem install -r skills/video-production-tools/requirements.txt`。其他系统用自己受信任的证书路径；不要关闭验证或添加不受信任来源。
- 显示未配置环境变量，但macOS已保存Key：自检故意不读钥匙串，这不代表Key一定丢失。生成器会按已记录的钥匙串服务读取；先dry-run，真正请求是否成功另看回执。
- dry-run成功：只说明请求参数可准备，不证明Key有效、额度充足或服务可用。
- 本地分析退出1但有报告：本地机械证据已准备，语义分析仍未完成，详见[工具命令](../skills/video-production-tools/references/operations.md)。
- 打标“发送”不可用：先保存意见再回当前对话通知；保存、发送和AI已修改是不同状态。
- 云服务401/403或额度/模型错误：检查对应服务的账号、API开通、项目和权限，不要换目录盲目重发可能已计费的请求。

这是测试预览版，尚未完成所有系统和新手实机验收。检查能明确暴露缺项，不能替代真实使用测试。
