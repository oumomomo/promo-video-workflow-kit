# 可携带的动效配方与源码

入口为本目录 `scripts/motion.py`，只需Python 3.10+即可检索、解析、导出。渲染另需Node/npm、Remotion/React与浏览器；网页交互动效还有各自依赖。本包没有安装这些运行时，也不把源码齐全称为所有效果已验证。

这是从统一库选出的**只读发行目录**：161种 video-shotcraft 镜头样式（104张卡）与202种 MotionVault 网页效果。当前生产库仍是原统一入口，本目录不作为本机新的可编辑素材主库；不导入或修改生产数据库。

## 分镜中怎样用

1. 围绕本镜的事件、焦点、材料和时序检索，不为套效果改脚本。`search` 可限制 `--runtime remotion` 或 `web_react_interaction`。命中是查阅，不是必须采用；允许复用、混合或原创。
2. 用真实ID `resolve`，完整读配方与所列准确源码；同一卡可能有多个实现，用 `demos` 路径区分，不凭卡名猜文件。
3. 选择 `reuse`、`remix` 或 `invent`。继承运动语法，替换成本片真实／新生成对象、品牌和文字。第三方示例的假UI、性能数字、文案只是演示数据，不能当真实产品功能依据。
4. `export` 带出配方、源码依赖和许可证；没有媒体文件。`missingMedia` 会列出需另备的截图、纹理或布局JSON。21条镜头样式有此缺口，不能直接声称开箱渲染。
5. 无媒体缺口的Remotion条目可 `scaffold` 创建单镜工程。明确组件、时长和当前素材，再安装依赖、查看关键帧／正常速度运动、适配后渲染。需要自带属性的组件须按源码补props，不能以脚手架建立成功代替渲染成功。
6. MotionVault是网页交互源码，hover、滚动、requestAnimationFrame、CSS／Framer Motion计时要改为确定的视频帧驱动；原代码不直接作为可逐帧重现的Remotion效果。读[使用与适配](references/usage.md)。
7. 用 `record` 把当前镜头、模式、来源版本、选择原因、改动和排除项写到项目；只写项目采用表。已配置统一库的生产环境继续按原入口提交正式采用记录，不用此副本替代生产真源。

配方、代码导出与运行方法见[使用与适配](references/usage.md)。来源、精确文件SHA、上游版本和许可在 `references/provenance.json`；第三方原代码未改，许可证分别保留。没有捆绑原动态预览、真实产品截图、音视频、字体、数据库、项目历史或私人路径。

## 与制作技能衔接

在 `video-making-kit` 的事件分镜确定时查本库；生成单镜动画后，将实际新视频用该技能的 `add-asset --kind video` 加入本片，再组合、混音与检查。不得拿示范假UI替代已有真实产品原件。新镜头和用户批准过的镜头分开，局部反馈保护其他画面、时长和音轨。

不要因库里有类似效果限制原创，也不要机械让每镜不同。正常速度结果是否服务叙事、整片是否连贯，比命中数量更重要。完整渲染、语义／声音检查与真人审美分别记录。
