# 扩展视频生产工具

配合制作宣传片时，读取同级`video-making-kit/references/promo-pitfalls.md`，将本次片段卡、视听证据、视觉合同、修改保护和验收记录关联到项目`workflow/promo-review.md`；沿用该制作技能的检查入口，不新造一份相互冲突的规则源。

先读[命令与状态边界](references/operations.md)，选择本次实际需要的环节。与同包video-reference-kit、video-asset-library、video-making-kit同级安装，根入口video_tools.py；数据库继续用现有统一入口或使用者自己已初始化的便携库。不要再建私有主库。详细视听、缓存、原片与验收方法见[检查方法](references/review-method.md)。

产品参考：先判产品原片/反馈/聊天/待判角色，intake复制校验，查看原件后填写segments；结构抽帧和连续动作核实分开。候选片段不发布，find命中也不是制作批准。严禁从多个产品页面拼出未观察过的功能因果。

自动分析：默认cloud none，只准备本地切点、帧变化和混音瞬态证据。video/audio云模式须使用自己的Google项目、凭据及覆盖源文件哈希/服务/模式的已有授权；保存原模型响应、分段状态和不确定项。模型描述只能是候选；没有听辨或连续观看不能称为细致复核完成。不要把声音瞬态当作已确认独立音效。包外Jev、受限站点获取和原作者音效文件识别不在此便携入口内。

声音：配音先选风格与dry-run，按已有用户授权合成，中文豆包、英文Google；使用者配置自己的凭据，不读取作者账号。缓存哈希校验失败不自动重新付费生成；同请求复用。费用按实际新增请求与用户核验的价格记录，未知保持未知。不要把模拟测试当作真实服务验收。音乐可通过music generate用使用者API Key生成，原Vertex ADC路径需显式选择；请求失败/不确定不自动重发。先登记使用者自己的原件与许可证据，plan自动按用途检索并检查文件/许可哈希与时长，apply接入现有剪辑计划，最后由制作执行器渲染；选中、写入计划、实际混入和听感通过是不同状态。

视觉：contract记录整片来源、连续性、配色依据和逐镜继承/调整/拒绝项；evidence检查原片身份、镜头粒度、实际帧与比较记录。程序只检查字段/哈希，不能代替实际目视对照或人类审美批准。

正式生产：ledger保存决策证据与不可变快照。批准/拒收须记录主体、范围和证据；工具不能认证证据作者，更不能替用户批准。局改前protect绑定原视频SHA与反馈，修改后verify检查未标镜头分镜/素材身份、实际解码帧与音轨。未标内容确需变化时说明具体范围并按已有授权另建合同，不能放松检查冒充通过。rollback恢复分镜、素材清单、脚本和视觉合同前先保存当前状态；不删除媒体和候选。正式归档仍遵守用户指定范围，候选和样片不自动进素材库。Univer界面投影、工作台任务服务和远程worktree未随此本地账本迁移。
