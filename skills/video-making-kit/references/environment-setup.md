# 首次接入：由AI检查并准备环境

用户交来仓库链接、解压包，或要求安装/开始使用时，先承担环境判断，不要求用户提前解释Git、Python或FFmpeg。安装授权覆盖的普通依赖准备可继续执行；缺管理员权限、宿主权限或交互登录时，只说明具体受阻步骤及用户需完成的操作，不反复询问已授权事项。

## 从没有Python的情况开始

1. 用宿主已有的终端/文件能力识别操作系统、处理器架构、当前工作目录和可用工具。先探测Python命令及版本，再决定能否运行`video_setup.py doctor`。Python不存在时，不把运行该脚本当成第一步。
2. 获取完整仓库。已有Git可克隆；没有Git就下载公开仓库/发行ZIP并解压，Git不是本地制作必需运行时。核对下载来源和完整目录，不只下载SKILL.md。
3. 判断本次任务需要哪些模块。基础制作只需Python3.10+和含libx264的FFmpeg/ffprobe；参考切镜再需Node18+，打标再需Node20+和npm。配音/分析的Python依赖按同包requirements安装；不要为首次静图/录屏剪辑先装全部动效生态或云服务。
4. 对可用版本直接复用；缺失项按当前系统与架构，从官方发行渠道或系统已有的包管理器安装。优先用户级安装或项目工具目录（例如`.runtime/`），Python依赖放项目虚拟环境。需要修改全局环境或管理员权限时遵循宿主权限要求，不覆盖系统Python或已有用户配置。包管理器本身没有安装时，选择官方安装/便携发行路径，不套用其他系统命令。
5. Python可用后运行仓库根目录`video_setup.py doctor`；使用项目工具目录时，让本次终端/子进程能找到实际二进制，再重新检查。不要写死作者电脑路径，也不要将下载完成或文件存在称作可执行已验证。
6. 从实际返回结果区分基础运行条件与可选缺项；配置了模块后执行对应`--feature`检查。打标依赖安装与MCP接入分别处理，安装依赖不等于宿主工具已注册。按`docs/首次使用.md`继续首条片。

## 无需在安装阶段填写全部密钥

基础剪辑、库管理、本地测量和打标本身不要求云Key。先用用户提供的有依据材料完成最小制作；只有当前任务需要生成或云分析时，再按`docs/密钥与服务配置.md`提示该服务配置。由用户在自己的安全输入/环境中填写，不在聊天中索要明文Key；不借用作者账号，不为验证安装调用付费服务。

本仓库目前没有捆绑Git/Python/FFmpeg二进制，也没有通用系统安装器。上述为宿主AI执行指引，不是已实现的自动安装程序；不能称“已内置运行环境”或保证所有AI/所有系统都能自动完成。宿主没有终端、网络或本地文件权限时，说明能力缺口，给出适合该系统的最少人工步骤。

## 完成条件

告诉用户：项目存放位置、实际使用的Python和FFmpeg、基础检查结果、本次已安装项和仍未配置的可选项，以及下一句可用于开始制作的请求。只报告实际执行范围。首次用户不必理解各工具名称，AI需要说明哪个步骤已完成、哪个具体步骤需要用户操作。

若准备便携运行环境，需要分别维护系统/架构的二进制及依赖；这可以另行实现，不把编写指引冒充已经交付的便携包。
