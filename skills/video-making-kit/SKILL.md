# 从题目到可审看的视频

交付实际视频和可编辑项目。不能把参考检索、空分镜、示例模板或命令执行成功当作视频效果。

本技能自带 `scripts/video_make.py`，仅需 Python 3.10+、FFmpeg/ffprobe（含 libx264）。无 Node、数据库、私人路径或其他已安装技能依赖。它处理剪辑与证据；创意、写稿和素材理解由当前宿主 AI 完成。图像／视频生成、TTS和音乐生成工具按实际可用性选择，可能收费；包内不含这些服务或额度。

## 输入与创意

先读[制作与验收](references/production.md)，再开始新片或修改。制作产品/品牌宣传片时，第一次分镜前、收到负面反馈后和交付前读取[宣传片避雷清单](references/promo-pitfalls.md)，按适用的P01–P24记录本片检查和未关闭问题；使用包根目录`templates/promo-review.md`建立`workflow/promo-review.md`。该清单不规定所有品牌沿用同一字体、配色、秒数或界面，不能把“已读”当效果通过。

- 只有题目：在用户授权范围内完成写稿和视觉方向。缺失的非关键选项可以明确假设后继续，不把每一步变成审批。真实品牌的产品功能、价格、承诺须有依据。虚构品牌测试要记录在项目中，不能称为真实商业效果。
- 已有定稿：保留原文，用 `lock-script --origin user_provided` 锁定；不因画面难做就改写。需要改稿时另存版本并遵守已有授权。
- 要验证安装包：使用全新任务与独立空目录，不偷偷调用旧工程、私有素材库或旧候选。系统运行时和新取得的公开依赖单独记录。使用旧录屏剪辑只能验证该剪辑场景。

## 执行

1. `doctor` 检查实际工具；`init --project <空目录> --brief <题目>` 建项目。说明观众、要记住的一件事、画幅、时长、声音需求。项目 JSON 是当前制作记录，不是另一套素材主库。
2. 先写脚本、选择具体视觉方向，再 `lock-script`。文件锁定只表示原文可核对，不等于用户批准。可先制作用户已授权的候选，不额外等批准。
3. 按视觉事件写 `workflow/plan.json`。每镜有起态→事件→结果、一个阅读中心、衔接、源素材和可观察的验收条件。脚本字符区间覆盖全部非空白内容，不能一句话自动配一页大字。参考可检索，但没有参考时允许原创，并记录色彩与对象依据。若同包 `video-motion-kit` 已安装，关键动态镜头定案前用其 `search`／`resolve` 查配方与准确源码，选择复用、混合或原创并写项目采用记录；它提供代码和方法，不提供旧媒体。单独安装本技能时不虚构拥有动效库，可按当前素材原创。
4. 准备本次的新素材。有真实产品原件先查看对应界面与连续动作，继承结构和行为，按本片替换业务内容；没有依据不能发明功能。有生成工具时制作需要的图像／视频并检查对象一致性、文字和物理关系。没有生成工具也没有适用媒体时，说明具体素材缺口，不用方块占位渲染后声称已完成。
5. 同包video-asset-library已接入时，按用途查自己的资料库，get核验后再查看实际原件；未接入不假装已检索。`add-asset` 复制实际采用素材并校验哈希；来源、权限依据逐项记录。字体、音效等依赖同样要拷入项目或明确安装。素材清单不授予公开再分发权。参考整理可选配同包的 `video-reference-kit`；它不是渲染前置依赖，有统一库时沿用原入口。
6. 用 `validate` 核对脚本、素材、时间与声音方案；先检查风险镜头的关键画面及实际运动。修复已看到的缺陷再 `render --out out/candidate-r01.mp4`。不要强制套用统一审美模板。内置执行器支持静图推拉／平移、视频裁切剪辑、透明图片叠层和多轨声音；人物动作、真实注水、复杂3D和界面操作须先用合适工具做成视频，不能把静图推拉称为这些动作已实现。
7. `check --file out/candidate-r01.mp4` 对最终编码文件全帧解码、核对时长、尺寸、帧数、音轨并抽取逐镜首中尾。抽帧还必须实际查看；正常速度整片观看、声音试听、真人审美与用户批准分别记录。缺失的检查保持待完成，候选可以交给用户审片，不伪造 pass。
8. 同包video-production-tools可用时，按任务使用产品片段卡、视觉合同/原片门禁、声音接入和局改账本；工具记录不代替批准。交付实际 MP4、工程与检查范围。本发行包带有视频打标插件源码与接入入口，安装说明见包根目录`docs/打标插件安装.md`；文件已打包不表示宿主已注册，先检查实际工具。宿主有 `codex-video-review` 时打开真实文件的打标页，确认能播放与画标记；没有插件则交付本地视频并说明没有该标注能力。不要虚构接口或把工具 queued 说成已打开。

详细命令、分镜格式及渲染边界见[可执行协议](references/commands.md)。不要照抄某个测试题目作为所有新片的分镜。

## 修改与状态

修改先核对被标文件 SHA-256，写清问题、基线、改变与保护范围。素材和输出用新ID／文件名，保留旧候选。局部修改保护未标镜头、时长和音轨；若必须扩大范围，解释具体影响并按用户现有授权处理。

`rendered_candidate`、`technical_pass`、真人认可与发布授权是不同状态。程序不自动入素材库、不上传、不发布、不改宿主全局配置，不会因为文件名有 final 就登记成片。
